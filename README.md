# Ren'Py 自动汉化工具 (rpytranslator)

> 当前版本：**v0.1.9**（详细变更见 [CHANGELOG.md](CHANGELOG.md)）

将 Ren'Py 游戏自动汉化为简体/繁体中文：识别游戏文本 → AI 翻译 → 一键生成汉化补丁。

## v0.1.9 重点

- **繁体残留一键修复**：简体中文目标下，模型输出的繁体（无论零星还是整段）
  不会再进游戏——译文写盘前逐字归一化（内置 999 个无歧义字对，著/乾/藉 等
  同形字不碰）；已存在的繁体翻译由「补漏查缺」**本地直接改写为简体**（零
  API 成本，实测 55 条一键转简、复扫清零），不占用重译名额。
- **未翻译残留根因修复**：「译文==原文」不再被一刀切视为模型有意保持——
  原文含成串英文的回退一律进重译队列，终结「多次查缺仍残留」的循环；
  未翻译报告支持多行/反斜杠原文的精确往返。
- **字体选项并入游戏原生列表**：游戏自带 Font 选择时，汉化字体直接追加在
  原生列表里（同样式），不再出现两个 Font 段；无原生列表才注入自有段
  （仅切换到中文后显示）。
- **语言选项丢失修复**：语言检测不再被工具自己注入的补丁/注释误导；
  「已注入」判定要求实际看到语言按钮代码，坏文件自动重建。
- **提示词加固**：全部四个提示词模板增加「译文必须是纯目标语言、禁止保留
  英文句子（专有名词/人名/占位符除外）、简体目标严禁简繁混用」。

## v0.1.8 重点

- **补漏查缺**：翻译完成后自动扫描已生成的翻译，分类检出三类残留问题——
  **未翻译残留**（译文与原文相同）、**中英参半**（残留成段英文）、
  **目标语言不正确**（含其他语言文字或整句英文）。报告写入
  `tl/<语言>.补漏查缺报告.txt`（含 文件:行号 定位），问题项自动排入重译
  队列——再次点击「开始汉化」即可只重译这些条目，形成补充修正闭环。
  GUI 另有手动「补漏查缺」按钮，随时可对已翻译的游戏单独扫描。
- **设置界面字体选项**：游戏设置里新增「字体」单选——**汉化默认字体 /
  系统微软雅黑**（不复制文件，直接引用 Windows Fonts）。切换即时作用于
  游戏内所有文本（GUI 变量、命名样式、屏幕内联 `font=` 元素经
  `font_replacement_map` 全覆盖），选择跨启动记忆。
- **已知局限**：游戏主菜单按钮英文烤在 PNG 里（`imagebutton`），
  文本工具无法触及。

## v0.1.7 重点

- **暂停与断点续译**：翻译中可随时点击「⏸ 暂停」，当前请求完成后立即停止；
  已译内容实时保存（`tl/.{语言}.汉化进度.json`），未完成段落写入暂停标记
  （`tl/.{语言}.暂停标记.txt`，按顺序列出剩余条目）。退出程序后重新点击
  「开始汉化」，自动从暂停标记处顺序续译，无需从头开始；完成后标记自动清理。
- **本地模型连接修复**：`localhost` 同时解析出 IPv6/IPv4 时不再误报
  “目标计算机积极拒绝”(WinError 10061)；连接错误给出可操作排查建议；
  检测到模型“原样返回不翻译”（机器翻译模型被用于不支持的语向）时明确警告。
- **提示词自动适配**：按模型实际返回行为自动选择提示词风格，机器翻译类模型
  会自动切换到精简英文提示词，**无需针对具体模型做任何配置**。
- **译文质量把关**：批量失败自动折半重试；剥掉模型套在译文外的 `["…"]` /
  `{"response": …}` / 代码块外壳；拒收残留占位符与「聊天式回应」。宁可该条
  回退原文并计入未翻译报告，也不让乱码进游戏。
- **本地推理吞吐**：检测到本地端点时自动并发 4 路请求，GPU 利用率显著提升
  （串行单请求时 GPU 大部分时间在空等）。
- **进度倒计时**：进度百分比旁显示预计剩余时间（指数平滑估算）。

## v0.1.4 重点

- **游戏更新自动补译**：游戏升级（脚本/剧情变化）后重新点击「开始汉化」，
  工具自动识别 `tl/<语言>` 已有的译文，**只翻译新增 / 修改部分**；旧译文 100%
  保留，已删除剧情自动消失。日志会显示“本次需补译 N 条、其余 M 条已有译文将全部保留”。
- **保护机制**：检测到官方/手写 `tl/` 无法解析为标准翻译块时，跳过并保留原目录，
  不会误覆盖。
- **代码优化**：`extract.decode_say_string` 统一去 `@@pN@@p` 残留并供全模块共用，
  重复解析 `_parse_existing_tl` 的结果在 5.2 检测与组装两步之间共享。

## 功能特性

- **自动识别**：解析 Ren'Py 游戏目录，读取 `.rpy` / `.rpyc` 脚本并提取全部对白文本（同文件同时存在 `.rpy` 与 `.rpyc` 时按 Ren'Py 优先级只处理 `.rpy`，避免重复翻译块）
- **RPA 归档支持**：脚本被打包进 `.rpa` 归档（game 目录无松散脚本）的发行版也能汉化——自动解析 RPA-3.0/2.0 归档索引，抽取其中的 `.rpyc` 编译脚本（Ren'Py 实际加载的产物，翻译 identifier 与之对齐），资源文件（图片/音频）不解出
- **命名菜单识别**：`menu 名字:` 是 Ren'Py 的隐式 label，其作用域内（含菜单之后到下一个 `label` 前）的对话 identifier 前缀为菜单名，提取器与 Ren'Py 实际编译结果逐字节一致，翻译必定命中
- **增量翻译复用**：再次汉化时自动加载已有 `tl/` 译文；即使提取逻辑升级导致 identifier 前缀变化，也能按翻译 ID 的摘要段（md5 前 8 位，由文本内容决定、与 label 无关）兜底匹配，旧译文不会丢失
- **编译残留清理**：解析已有译文时自动剥离 Ren'Py 编译产物（如 unrpyc 反编译）中残留的 `@@pN@@p` 块位置标记，保留 `@@nN@@` / `@@pN@@` 插值占位符，保证译文干净且插值完整
- **完整覆盖**：按源文件相对路径生成翻译文件（保留子目录结构，`days/route_aelfric/day_6.rpy` 与 `days/route_ulrich/day_6.rpy` 不会互相覆盖）；同文本重复出现也全部写入译文
- **角色名保留**：角色名（`Character("...")`、`xxxVars.name = "..."`）自动保留原文不翻译；AI 提示词要求人名、角色名一律不译
- **AI 翻译**：支持任意 OpenAI 兼容接口（OpenAI / DeepSeek / Kimi / 通义千问 / 智谱 GLM / Ollama 本地等），批量翻译、智能重试，失败回退原文并生成「未翻译报告.txt」定位遗漏
- **自动补译**：首轮翻译后自动检测仍未翻译的文本并循环重译，直到全部汉化完成；只有多次补译后仍失败时才保留「未翻译报告.txt」（此时其内容即为需要手动补充/排查的部分）
- **运行时翻译验证与自动补译（解决“部分中文部分英文”）**：汉化完成后自动向游戏注入验证补丁（`zz_verify_translations.rpy`，可删除）。游戏启动时由 Ren'Py 用自身对话翻译注册表（`default_translates` / `language_translates`）精确比对，把**运行时实际缺少翻译**的对话导出为「`tl/<语言>.运行时缺失报告.txt`」——包括反编译/提取覆盖不到（特殊属性写法、NVL 多行段落、identifier 与官方不一致等）而主流程无法感知的漏译。再次汉化时若发现该报告，工具按**运行时 identifier** 自动补译（优先复用已有译文、缺失走 AI，自动识别并跳过无文字的空对话/符号/纯换行段），生成 `zz_missing_fix.rpy` 逐条命中。空对话、`!`、`...`、`{nw}`、纯 `\\n` 留白等无文字条目不会误报
- **报告驱动增量汉化**：再次拖入已汉化过的游戏时，若发现仍存在「未翻译报告.txt」，将自动只翻译报告中列出的文本（跳过已有译文的条目），并保留上次已翻译成功的内容；每次汉化结束后自动更新报告，直到全部完成、报告消失
- **智能判定未翻译**：代码性文本（样式属性、资源路径、字典键、颜色等）不会被误提取为对话；若整个汉化过程无任何翻译错误、剩余文本只是模型有意保持原文（专有名词、键盘键名等），则视为已处理、不生成报告——报告仅在存在真实翻译错误时保留，方便定位问题
- **一键补丁**：自动生成 `game/tl/<语言>/` 汉化补丁目录，可直接放入游戏生效
- **中文适配**：可选自动配置中文字体、注入语言切换界面
- **现代化界面**：WinUI 3 (Fluent Design) 界面，支持拖放选择游戏目录、Mica 磨砂背景

## 快速开始

### 方式一：直接使用可执行文件

下载 [Releases](https://github.com/haohan-hh/Machine_translated_Renpy_game/releases) 中的 `RenPyTranslator.exe`，双击运行即可（Windows 10 1809+ 或 Windows 11）。

### 方式二：源码运行

需要 Python 3.10+，并安装 Windows App Runtime 1.5：

```bash
pip install -r requirements.txt
python main.py --gui          # 图形界面
python main.py --cli 游戏目录 --api-key sk-xxx   # 命令行模式
```

## 使用方法

1. 启动程序后，将 Ren'Py 游戏文件夹拖入窗口（或点击“浏览…”选择）
2. 选择翻译服务，填写 API 地址 / Key / 模型（配置会自动保存）
3. 选择目标语言，点击「开始汉化」
4. 完成后打开输出目录，将补丁放入游戏根目录即可生效

## 命令行模式

```bash
python main.py --cli <游戏目录> [选项]
```

| 选项 | 说明 | 默认值 |
| --- | --- | --- |
| `--api-url` | 翻译服务地址 | `https://api.openai.com/v1` |
| `--api-key` | API Key | 无 |
| `--model` | 模型名 | `gpt-4o-mini` |
| `--lang` | 目标语言 | `schinese` |
| `--no-font-patch` | 跳过中文字体配置 | - |
| `--no-lang-ui` | 跳过语言切换界面 | - |
| `--no-verify` | 跳过注入运行时翻译验证补丁 | - |

## 常见问题与自动预防（实战经验）

以下问题均来自真实游戏汉化过程，工具已内置对应预防/自动处理机制。

### 汉化完成，但游戏里“有的角色中文、有的角色英文”

**根因**：汉化流程基于“反编译脚本”提取文本，只能确认“提取到的文本都翻完了”，
无法确认“游戏运行时显示的所有对话都有翻译”。个别对话可能因写法特殊
（如 `Mikko strained "..."` 的裸词属性）、反编译与官方 identifier 不一致、
NVL 多行段落等从未被提取——工具自认为 100% 完成，游戏里却是英文。

**自动闭环**：
1. 汉化完成时工具向游戏注入验证补丁 `zz_verify_translations.rpy`；
2. 启动一次游戏，Ren'Py 用自身注册表精确比对，把运行时实际缺少翻译的对话
   导出为 `game/tl/<语言>.运行时缺失报告.txt`；
3. 再次运行汉化工具，检测到该报告后自动按运行时 identifier 补译
   （生成 `game/tl/<语言>/zz_missing_fix.rpy`），逐条命中、不重复翻译已有内容；
4. 再次启动游戏校验，直到报告里只剩空对话/符号（无实际文本）即为完整状态。

补丁文件（`zz_verify_translations.rpy` / `zz_missing_fix.rpy`）均以 `zz_` 前缀命名，
可随时删除；删除后对应验证/修复即回退。

### 为什么报告里剩余的空对话 / `!` / `...` / `{nw}` / 纯 `\n` 段不用管

这些是 Ren'Py 的停顿、转场与留白节点（如 `""` 空句、NVL 换行段落），
不显示任何文字，未翻译不会产生英文内容，因此验证与自动补译都会跳过它们。

### 角色带情绪/状态的台词（`Mikko strained "..."`）已兼容

Ren'Py 官方语法允许 say 属性写成裸词（不带 `+`/`-`）。提取器按 Ren'Py 官方
`say_attributes` 语法解析，此类对话不会漏提取。

### 为什么汉化后要先删一次旧 `.rpyc` 缓存

Ren'Py 运行时优先加载 `.rpyc`。若旧缓存是汉化前编译的（不含翻译），游戏会继续
显示英文原文——这是“汉化没生效”最常见的原因。工具在汉化后会自动清理有对应
`.rpy` 源文件的过期缓存，下次启动即从源文件 + `tl/` 重新编译。

### NVL 模式（多行旁白）如何保证翻译质量

NVL 段落的 `what` 以多个 `\n` 空行开头（`\n\n\n\n文本…`）。补译时只把正文交给
AI、保留前导空行结构，译文写回时以字面 `\n` 转义与 Ren'Py 语法一致，
避免整段多行文本在模型往返中丢失占位符。

## 项目结构

```
main.py                    # 入口（GUI / CLI）
rpytranslator/
  engine.py                # Ren'Py 游戏扫描与文本提取
  translator.py            # OpenAI 兼容翻译客户端（支持并发）
  pipeline.py              # 汉化流程编排
  patcher.py               # 字体与语言界面注入
  generator.py             # 翻译文件生成
  housekeeping.py          # 汉化后自动化：清理过期 .rpyc 缓存、去重 translate 块
  verify.py                # 运行时翻译验证补丁 + 缺失报告解析 + 自动补译
  rpa_loader.py            # .rpa 归档解析与脚本抽取（RPA-3.0 / RPA-2.0）
  gui_main.py              # WinUI 3 图形界面
```
